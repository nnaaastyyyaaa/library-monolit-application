Звіт з лабораторної роботи №4: Синхронна та асинхронна комунікація між компонентами

## Мета роботи
Навчитися організовувати взаємодію між компонентами системи, реалізуючи синхронний та асинхронний підходи для оптимізації архітектури та покращення швидкодії.

## Опис виконаних завдань

### 1. Виділення допоміжних компонентів та побічних операцій
Було виділено наступні операції:
* **Синхронна операція:** Перевірка автентифікації користувача (валідація токена).
* **Асинхронні операції (побічні):** Надсилання Email-повідомлення користувачу про успішне бронювання.

### 2. Реалізація синхронної взаємодії
Для авторизації було створено окремий сервіс `AuthService`. Взаємодія з ним відбувається синхронно безпосередньо в обробнику команди. Це критично важлива операція: якщо токен невалідний, система повинна негайно перервати виконання і повернути помилку, не переходячи до бізнес-логіки.

### 3. Реалізація асинхронної взаємодії
Для виконання операцій, які не впливають на результат створення резервації (Email), використано патерн Event Bus.
Після успішного збереження резервації в БД публікується подія. Ця подія обробляється асинхронно через setImmediate, що дозволяє миттєво повернути відповідь клієнту, не чекаючи завершення роботи побічних сервісів.

До події підписані:
Email Service: Надсилає повідомлення через SMTP.

### Висновки
Синхронна комунікація ідеально підходить для критичних перевірок, без яких подальше виконання бізнес-процесу не має сенсу (наприклад, безпека).

Асинхронна комунікація дозволяє значно підвищити "чуйність" системи для користувача, виносячи некритичні дії (нотифікації) за межі основного циклу запит-відповідь.

Для production-системи найкращим є гібридний підхід, який і був продемонстрований у проекті.
