Опис проведених змін
1. Впровадження патерну CQS
Логіку, яка раніше знаходилася безпосередньо в контролерах, було винесено в окремі обробники (Handlers). Це дозволило розділити операції на два типи:

Commands (Команди): Операції, що змінюють стан системи (Create, Update, Delete).

Приклад: CreateUserHandler, DeleteReservationHandler.

Використовують репозиторії для запису даних.

Queries (Запити): Операції, що лише повертають дані без зміни стану.

Приклад: GetUserHandler, GetUsersHandler.

Працюють безпосередньо з Prisma для максимальної продуктивності.

2. Впровадження Dependency Injection (DI)
Для керування залежностями було створено спеціальні файли-контейнери в папці container/. Це дозволило:

Уникнути жорсткого зв'язування (Tight Coupling) між класами.

Легко підміняти реальні репозиторії на "заглушки" (Mocks) під час тестування.

Централізовано ініціалізувати всі сервіси, хендлери та контролери.

2.3 Рефакторинг контролерів
Контролери були перетворені на "тонкі" компоненти. Тепер їхня єдина роль — отримати HTTP-запит, сформувати об'єкт команди або запиту (DTO) та передати його відповідному хендлеру.

3. Технічні деталі реалізації
Структура папок після рефакторингу:
application/commands/ — логіка зміни даних.

application/queries/ — логіка отримання даних.

container/ — конфігурація залежностей (складання об'єктів).

infrastructure/ — робота з базою даних (Prisma) та зовнішніми сервісами (JWT).

presentation/ — маршрути (Routes) та контролери.

4. Тестування
Для перевірки працездатності системи було реалізовано:

Unit-тести: Для перевірки бізнес-логіки хендлерів в ізоляції від бази даних.

Integration-тести: Для перевірки повного циклу запиту за допомогою supertest.

Результати тестування:

Тести getUserHandler підтвердили коректність вибірки даних.

5. Висновки
В результаті виконання лабораторної роботи застосунок став більш модульним та придатним для масштабування. Впровадження CQS дозволило зробити код більш читабельним та полегшило написання тестів. Використання Dependency Injection спростило підтримку коду, дозволяючи змінювати реалізацію окремих частин системи (наприклад, перейти з Prisma на іншу ORM) з мінімальними змінами в інших модулях.
